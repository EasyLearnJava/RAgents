What you learn
  • Splitting an app into a frontend (this page, in your browser) and a backend (Python on a server) that talk over HTTP, with JSON going both ways
  • FastAPI: each endpoint is a Python function (chat(), health()), and FastAPI turns the JSON body into a Python object and the result back into JSON
  • Validation on the server: ChatIn allows at most 1000 characters, and FastAPI refuses anything longer (422) before your code runs
  • The same chain as step 3, in Python's LangChain: normalize | rules
  • Local and live: the same code runs under uvicorn on your computer and as a Vercel Python function on the live site
How a message travels
  1. index.html: onSend(e) adds your bubble and "thinking…", then api() sends it with fetch: POST /api/step4/chat, the body {"message": …} as JSON. The page doesn't check the text: even an empty message goes to the server, and the chain answers it.
  2. Vercel (live): HTTPS ends at Vercel's front door, and vercel.json sends every /api/* request to the Python function api/index.py, which loads main.py's FastAPI app. Locally, the site server forwards /api/* to uvicorn instead.
  3. main.py: FastAPI reads the JSON into ChatIn. More than 1000 characters is refused here (422); otherwise it calls chat(body), which calls run_with_events(message).
  4. agent.py: run_with_events() runs the chain with astream_events(), keeps each named step's events and times the whole run (server_ms).
  5. Back: chat() returns { reply, rule, events, server_ms }, FastAPI sends it as JSON, api() parses it and add() shows the reply. The street view lights the chain's board from those events, so it shows what really ran on the server.
Errors and limits
  • 422, too long: more than 1000 characters. The box takes 1100 on purpose, so you can try it: FastAPI refuses it before chat() runs, and the chain never sees it.
  • 502, backend not running: locally, the site server couldn't reach uvicorn on 127.0.0.1:8000. Start it (see the README) and reload the page.
  • 404, not deployed: a site with no Python backend behind /api/* answers 404 or a web page instead of JSON, e.g. the Firebase Hosting copy (ragent-eec65.web.app).
  • Network error: no answer at all (offline, or the server can't be reached). api() never throws: it returns { ok: false, status: 0 } and the chat says so.
  • Cold starts: Vercel starts a copy of the function when a request needs one and stops it after it's been idle. A message that finds none waits for Python to start and load FastAPI and LangChain, which can add a second or more. "Where the time went" shows it in the "there and back" stage.
  • Time limits: Vercel stops the function after 10 seconds (maxDuration in vercel.json). The page has no limit of its own: it waits for fetch, with "thinking…" showing and Send turned off.
Safety
  • Checked on the server: the 1000-character limit is in main.py (ChatIn), because anyone can call /api/step4/chat without this page (e.g. with curl) and skip any check in the browser. The box's 1100 is only a convenience.
  • No keys yet: this step has no model, so there's nothing secret in the page, the repo or the server: it only runs the rules.
  • Same origin, so no CORS: the page and /api share one address, so the browser allows the call without CORS headers. main.py adds none, so a page on another site can't read its answers in a visitor's browser.
  • No script injection: replies and error messages go on the page with textContent, so text that looks like HTML is just text.
  • The endpoint is public: scripts can call it directly. That's fine for rules that cost no money, though a flood could still use up the free request quota (see the README's safety notes). Step 5 adds App Check on the server before Gemini moves there, because then every call costs quota.
  • Limits: Vercel stops a call after 10 seconds. Locally everything binds to 127.0.0.1, so nothing else on your network can reach it.

Is my message private? To Review

Short answer: live, it's encrypted on the way, so strangers on the network can't read it. The server reads it, because it has to answer it.

  • HTTPS for the whole trip (live): the page and /api/step4/chat are on the same Vercel site, over HTTPS. .app domains are HTTPS-only (on the browsers' HSTS preload list), so it can't be downgraded to plain HTTP.
  • What an eavesdropper sees (same Wi-Fi, internet provider): which site you talk to, roughly how big each message is and when. Not the text.
  • Vercel sees it: HTTPS ends at Vercel's front door, so Vercel's servers handle the request in plain form and pass it to the Python function, which reads it to run the rules. Vercel, as the host, keeps request logs of its own; the app adds nothing of yours to them.
  • The code keeps nothing: main.py and agent.py don't log, print or store your message. It goes back to your browser in two places only: the reply's events (normalize's output is your trimmed text) and FastAPI's 422, which repeats your whole text (its input).
  • Locally: plain HTTP on 127.0.0.1, which never leaves your computer. uvicorn prints one line per request in its terminal: the client address, the method, the path and the status, not your text.
  • A company network that inspects HTTPS (e.g. Zscaler) decrypts and re-encrypts traffic, so its proxy can read your messages.

Check it yourself: F12 → Network, send a message and click chat: Payload shows what was sent and Response the JSON that came back. Only your browser shows them in readable form.
